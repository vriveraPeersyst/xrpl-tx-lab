## What changes

Before moving funds, the payment engine converts the transaction's `Paths` into "strands": sequences of concrete steps (trust line, order book, account). During that preparation process there was a bug that rejected some correct paths as malformed, in particular those that included an issuer step followed by a currency change. The payment failed with `temBAD_PATH` or similar even though liquidity existed.

fix1373 fixes the strand-building logic so those paths are accepted and evaluated normally. It also adjusts validation so that genuinely invalid paths continue to be rejected.

## Affected transactions and objects

- [Payment](/tx/Payment) with explicit `Paths` or automatic path-finding.
- [OfferCreate](/tx/OfferCreate), which internally builds strands to cross offers.
- [RippleState](/objects/RippleState) and [Offer](/objects/Offer) objects traversed by those paths.

## Status and context

Numbered after rippled issue #1373. It was introduced in version 0.90.0 alongside other payment engine fixes. In the current code it is retired (`XRPL_RETIRE_FIX(1373)`), so the correction is the base behavior. If you work with multi-currency payments on testnet you don't need to do anything special: the paths this fix enabled have worked for years.
