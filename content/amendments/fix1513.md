## What changes

rippled long ago introduced an internal mechanism called `STAmountCalcSwitchovers` to change, in an amendment-controlled way, how amounts (`STAmount`) are rounded and multiplied. The problem was that, when the FeeEscalation amendment was active, the code path that processes transactions in the fee queue did not consult that mechanism and kept using the old arithmetic. Two parts of the server could compute the same amount with different rules.

fix1513 makes all transaction application use the correct rule set for the ledger in which it's applied, so results are consistent regardless of which amendments are active.

## Affected transactions and objects

Any transaction that multiplies or divides issued token amounts: [Payment](/tx/Payment), [OfferCreate](/tx/OfferCreate), [TrustSet](/tx/TrustSet) with transfer fees, etc. It doesn't change the format of any ledger object.

## Status and context

Numbered after rippled issue #1513. It was introduced in version 1.4.0. Today it is retired (`XRPL_RETIRE_FIX(1513)`) and so is FeeEscalation, so the split between "old code" and "new code" no longer exists: only the corrected arithmetic remains. It's transparent to the user, but it explains why in rippled every rounding change is wrapped in an amendment.
