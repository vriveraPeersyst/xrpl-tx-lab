## What changes

When [EscrowCreate](/tx/EscrowCreate) creates an [Escrow](/objects/Escrow) object, it is linked into the owner's (`Owner`) directory so that `account_objects` returns it. Before fix1523 it was only linked into the sender's directory: the recipient had no way to discover via `account_objects` that an escrow was waiting for them, and it also didn't show up in their account history (`account_tx`), because the object didn't "touch" their account.

With fix1523 active, `EscrowCreate` also adds the escrow to the `Destination` account's directory (when it's different from the `Owner`) and stores the `DestinationNode` field in the object with that directory's page. [EscrowFinish](/tx/EscrowFinish) and [EscrowCancel](/tx/EscrowCancel) remove it from both directories when the object is deleted. It only counts toward the owner's reserve, not the destination's.

## Affected transactions and objects

- [EscrowCreate](/tx/EscrowCreate), [EscrowFinish](/tx/EscrowFinish), [EscrowCancel](/tx/EscrowCancel).
- [Escrow](/objects/Escrow): `DestinationNode` field.
- The recipient's [DirectoryNode](/objects/DirectoryNode).

## Status and context

Numbered after rippled issue #1523. It was introduced in version 1.2.0 and is retired in the code (`XRPL_RETIRE_FIX(1523)`). Escrows created before its activation don't have `DestinationNode`, which is why the field is optional in the object's format. On testnet, if you create an escrow to another account and query `account_objects` for that account with `type: escrow`, you'll see it thanks to this fix.
