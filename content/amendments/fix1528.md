## What changes

Every ledger carries a `close_time` that validators agree on during consensus. Under certain timing conditions (validators with slightly misaligned clocks and very tight consensus rounds), different validators could converge on the same set of transactions but with a different close time. Since `close_time` is part of the ledger's hash, that produced different hashes for the "same" ledger and forced additional rounds to resolve it.

fix1528 changes the rule used to round and agree on the close time so that, given the same set of proposals, all validators arrive at exactly the same `close_time`.

## Affected transactions and objects

It doesn't affect any specific transaction or the format of any object. It affects the consensus process and, therefore, any logic that depends on the ledger's close time: expirations of [Offer](/objects/Offer), deadlines of [Escrow](/objects/Escrow) (`FinishAfter`, `CancelAfter`) and of [PayChannel](/objects/PayChannel), which are compared against `parentCloseTime`.

## Status and context

Numbered after rippled issue #1528. It was introduced in version 1.3.0 and is retired in the current code (`XRPL_RETIRE_FIX(1528)`). It's more a consensus infrastructure fix than a transaction protocol one, but it needed an amendment because it changes how a ledger field that everyone must reproduce bit-for-bit is calculated.
