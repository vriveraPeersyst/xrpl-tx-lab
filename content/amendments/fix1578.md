## What changes

Adjusts two error codes:

- **[OfferCreate](/tx/OfferCreate) with `tfFillOrKill` that can't be fully executed.** Previously the transaction applied with `tesSUCCESS` even when the offer was "killed" without crossing anything, which confused clients that interpreted `tesSUCCESS` as "it executed". With fix1578 the result is `tecKILLED`: the transaction enters the ledger and pays the fee, but it's clear there was no exchange.

- **[TrustSet](/tx/TrustSet) trying to enable `tfSetNoRipple` on a line with a negative balance.** The protocol doesn't allow setting NoRipple on a line where the account owes tokens (a negative balance from its point of view). Previously the failure was silent or returned a generic code; with fix1578 it returns `tecNO_PERMISSION`.

## Affected transactions and objects

- [OfferCreate](/tx/OfferCreate) and the [Offer](/objects/Offer) object.
- [TrustSet](/tx/TrustSet) and the [RippleState](/objects/RippleState) object (`lsfLowNoRipple`/`lsfHighNoRipple` flags).

## Status and context

Numbered after rippled issue #1578. It was introduced in version 1.4.0 and is retired in the code (`XRPL_RETIRE_FIX(1578)`). The `tecKILLED` code you see today when testing `tfFillOrKill` or `tfImmediateOrCancel` on testnet originated with this fix; the variant for `tfImmediateOrCancel` came later with the ImmediateOfferKilled amendment.
