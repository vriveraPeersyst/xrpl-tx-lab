## What changes

[CheckCash](/tx/CheckCash) lets you cash a [Check](/objects/Check) in two ways: with `Amount` (an exact amount) or with `DeliverMin` (cashes as much as possible up to the check's `SendMax`, with a minimum). In the second case the amount actually received doesn't appear in the transaction; it can only be inferred from the balance changes in the metadata. Clients had to reconstruct it by hand, and it was easy to get wrong.

With fix1623, when `CheckCash` uses `DeliverMin`, rippled writes the `DeliveredAmount` field into the metadata (and exposes it as `delivered_amount` in RPC responses), the same way it does with partial payments of [Payment](/tx/Payment). If the check is cashed with `Amount`, this isn't needed because the amount is already exact.

## Affected transactions and objects

- [CheckCash](/tx/CheckCash): transaction metadata.
- [Check](/objects/Check): its format doesn't change.

## Status and context

Numbered after rippled issue #1623. It was introduced in version 1.5.0 and is retired in the code (`XRPL_RETIRE_FIX(1623)`). General rule for integrators: to know how much actually arrived at an account, always read `delivered_amount` from the metadata, never the transaction's `Amount`. This fix extends that guarantee to checks; years later [fixMPTDeliveredAmount](/amendments/fixMPTDeliveredAmount) did the same for direct MPT payments.
