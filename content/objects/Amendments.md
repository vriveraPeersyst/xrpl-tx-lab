## What it represents

`Amendments` is a *singleton*: only one object of this type exists in the entire ledger, and no one owns it. It is the official record of which protocol changes are active. When rippled's code asks `view.rules().enabled(featureX)`, it's looking here.

It contains two lists: `Amendments`, the 256-bit identifiers of amendments already permanently activated, and `Majorities`, the ones with at least 80% of UNL votes that have not yet completed the two weeks of sustained majority.

## Lifecycle

It is maintained by the network, not by users. No transaction can be submitted to modify it: the pseudo-type [EnableAmendment](/tx/EnableAmendment) is generated by validators within *flag ledgers* (one out of every 256) and is applied without a signature or a fee.

- With the `tfGotMajority` flag, `Change::applyAmendment` adds an entry to `Majorities` with `CloseTime` set to the moment the majority was reached.
- With `tfLostMajority`, it removes it.
- With no flags, once the majority has held for 14 uninterrupted days, it moves the amendment to `Amendments` and activates it. From that ledger onward, nodes that don't support it become *amendment blocked*.

The object is created at the first `EnableAmendment` in the network's history and is never deleted. Amendments already activated cannot be deactivated; they can only be retired from the codebase in future versions (the `XRPL_RETIRE_FEATURE` lines in `features.macro`), at which point their behavior becomes the standard.

## Key fields

- **Amendments** — array of hashes (each amendment's ID is the SHA-512Half of its name). On testnet today this includes, among others, `AMM`, `Credentials`, `MPTokensV1`, `PermissionedDomains`, `PriceOracle`, `TokenEscrow`, and `XRPFees`.
- **Majorities** — array of `Majority` objects with `Amendment` (hash) and `CloseTime` (seconds since the Ripple Epoch, 2000-01-01). If an amendment has been here for more than 14 days and still hasn't activated, it lost and regained majority.
- **PreviousTxnID / PreviousTxnLgrSeq** — the last `EnableAmendment` applied. These are optional because older ledgers didn't store them ([fixPreviousTxnID](/amendments/fixPreviousTxnID)).

## Flags

It has no `lsf*` flags.

## How to query it

The convenient way is the `feature` command, which returns the names. To see the raw object, use `ledger_entry` with `amendments: true`; the key is fixed, `SHA512Half(0x0066)` (`keylet::amendments`), and always equals `7DB0788C020F02780A673DC74757F23823FA3014C1866E72CC4CD8B226CD6EF4`:

```json
{ "method": "ledger_entry", "params": [{ "amendments": true, "ledger_index": "validated" }] }
```

Typical response (trimmed):

```json
{
  "index": "7DB0788C020F02780A673DC74757F23823FA3014C1866E72CC4CD8B226CD6EF4",
  "node": {
    "LedgerEntryType": "Amendments",
    "Amendments": [
      "8CC0774A3BF66D1D22E76BBDA8E8A232E6B6313834301B3B23E8601196AE6455",
      "726F944886BCDF7433203787E93DD9AA87FAB74DFE3AF4785BA03BEFC97ADA1F"
    ],
    "Majorities": [
      { "Majority": { "Amendment": "A1B2C3D4E5F60718293A4B5C6D7E8F9A0B1C2D3E4F5A6B7C8D9E0F1A2B3C4D5E", "CloseTime": 811410000 } }
    ],
    "Flags": 0,
    "PreviousTxnID": "3C2B1A0F9E8D7C6B5A4F3E2D1C0B9A8F7E6D5C4B3A2F1E0D9C8B7A6F5E4D3C2B",
    "PreviousTxnLgrSeq": 20799744
  }
}
```

It does not appear in any account's `account_objects`.
